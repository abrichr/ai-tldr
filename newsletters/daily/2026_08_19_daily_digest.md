<h2 style="margin: 0 0 8px; font-size: 24px; font-weight: 800; color: #f5f5f0; line-height: 1.2;">Mojo goes open source — Modular ships the compiler under Apache 2.0</h2>

<p style="margin: 0 0 20px; font-size: 15px; color: #8a8a85; line-height: 1.5;">Modular published the Mojo compiler and toolchain under Apache 2.0, four years after the language first appeared.</p>

<p style="margin: 0 0 16px; font-size: 15px; color: #f5f5f0; line-height: 1.6;">
<strong style="color: #f7ff00;">What is it?</strong><br>
The Mojo compiler source is public for the first time — released under Apache 2.0 with LLVM exceptions, together with the tooling and standard library, all inside the <a href="https://github.com/modular/modular" style="color: #f7ff00;">modular/modular</a> repository.
</p>

<p style="margin: 0 0 16px; font-size: 15px; color: #f5f5f0; line-height: 1.6;">
<strong style="color: #f7ff00;">How does it work?</strong><br>
Clone <code style="font-family: Menlo, Consolas, monospace; font-size: 13px;">modular/modular</code>, build with Bazel via the bundled <code style="font-family: Menlo, Consolas, monospace; font-size: 13px;">./bazelw</code> wrapper, then run any Mojo file. The standard library accepts contributions now; compiler patches open by end of year.
</p>

<p style="margin: 0 0 16px; font-size: 15px; color: #f5f5f0; line-height: 1.6;">
<strong style="color: #f7ff00;">Why does it matter?</strong><br>
Teams writing AI kernels can now read, fork and audit the compiler they depend on. The timing is deliberate: Mojo 1.0 shipped the week before with source stability, so the code people can read is the stable version they will build on.
</p>

<p style="margin: 0 0 20px; font-size: 15px; color: #f5f5f0; line-height: 1.6;">
<strong style="color: #f7ff00;">Who is it for?</strong><br>
Systems and GPU programmers who want a Python-compatible language built for AI performance without a closed-box compiler.
</p>

<h2 style="margin: 0 0 8px; font-size: 24px; font-weight: 800; color: #f5f5f0; line-height: 1.2;">Cerebras CS-4 — three wafer-scale chips per rack, 30x GPU token speed</h2>

<p style="margin: 0 0 20px; font-size: 15px; color: #8a8a85; line-height: 1.5;">Cerebras CS-4 puts three wafer-sized AI chips in one rack and aims squarely at GPU inference speed.</p>

<p style="margin: 0 0 16px; font-size: 15px; color: #f5f5f0; line-height: 1.6;">
<strong style="color: #f7ff00;">What is it?</strong><br>
The CS-4 is Cerebras' new rack-scale inference system built from three Wafer Scale Engine 3 Turbo processors — each a single wafer with 4 trillion transistors and 44 GB of on-wafer SRAM — delivering 750 PFLOPS per rack. First shipments begin this quarter.
</p>

<p style="margin: 0 0 16px; font-size: 15px; color: #f5f5f0; line-height: 1.6;">
<strong style="color: #f7ff00;">How does it work?</strong><br>
Weights live in on-wafer SRAM rather than external memory, eliminating the memory-bandwidth bottleneck that limits GPU inference. The rack hits 129.6 PB/s memory bandwidth and Direct Wafer Links join chips at 2 µs latency, enabling clusters to serve models above 50 trillion parameters.
</p>

<p style="margin: 0 0 16px; font-size: 15px; color: #f5f5f0; line-height: 1.6;">
<strong style="color: #f7ff00;">Why does it matter?</strong><br>
Cerebras reports 4,400+ tokens/sec/user on GPT-OSS-120B — up to 30x the per-user speed of GPU systems. Faster per-user throughput is what makes agentic reasoning feel snappy rather than slow, and 10x better throughput-per-watt matters for data-center economics.
</p>

<p style="margin: 0 0 20px; font-size: 15px; color: #f5f5f0; line-height: 1.6;">
<strong style="color: #f7ff00;">Who is it for?</strong><br>
Inference providers and teams serving frontier-scale models who need raw speed rather than commodity cloud pricing.
</p>

<h2 style="margin: 0 0 8px; font-size: 24px; font-weight: 800; color: #f5f5f0; line-height: 1.2;">CoSnitch — Copilot explained its own flaws, then leaked user data</h2>

<p style="margin: 0 0 20px; font-size: 15px; color: #8a8a85; line-height: 1.5;">Varonis chained three Microsoft Copilot Personal flaws so one clicked link could silently steal mail, files and chat history.</p>

<p style="margin: 0 0 16px; font-size: 15px; color: #f5f5f0; line-height: 1.6;">
<strong style="color: #f7ff00;">What is it?</strong><br>
CoSnitch (CVE-2026-24301) is a chain of three flaws in Microsoft Copilot Personal disclosed by Varonis Threat Labs. A single click on a crafted link ran an attacker's prompt inside the victim's signed-in session. Microsoft patched all three on August 18, 2026.
</p>

<p style="margin: 0 0 16px; font-size: 15px; color: #f5f5f0; line-height: 1.6;">
<strong style="color: #f7ff00;">How does it work?</strong><br>
Researchers used "meta-hacking" — asking Copilot why an attack wouldn't work, until it named the undocumented settings that made it work. An <code style="font-family: Menlo, Consolas, monospace; font-size: 13px;">?autorun=1</code> parameter made Copilot execute embedded prompts automatically; OAuth connectors then exfiltrated mail, files and chat history to the attacker.
</p>

<p style="margin: 0 0 16px; font-size: 15px; color: #f5f5f0; line-height: 1.6;">
<strong style="color: #f7ff00;">Why does it matter?</strong><br>
The memory-poisoning step is what makes CoSnitch worse than a normal data leak — injected instructions survive password resets and shape every later session. It's a named example of connector access plus persistent memory turning one click into ongoing compromise.
</p>

<p style="margin: 0 0 20px; font-size: 15px; color: #f5f5f0; line-height: 1.6;">
<strong style="color: #f7ff00;">Who is it for?</strong><br>
Security teams and admins reviewing AI assistants — and anyone with saved Copilot memories who should audit them now even though the exploit path is patched.
</p>

<h2 style="margin: 0 0 8px; font-size: 24px; font-weight: 800; color: #f5f5f0; line-height: 1.2;">Sentence Transformers v6.0 — ColBERT-style retrieval joins the library</h2>

<p style="margin: 0 0 20px; font-size: 15px; color: #8a8a85; line-height: 1.5;">Late interaction retrieval is now a built-in Sentence Transformers model type, not a separate framework.</p>

<p style="margin: 0 0 16px; font-size: 15px; color: #f5f5f0; line-height: 1.6;">
<strong style="color: #f7ff00;">What is it?</strong><br>
<code style="font-family: Menlo, Consolas, monospace; font-size: 13px;">MultiVectorEncoder</code> is Sentence Transformers' fourth model type (after dense, sparse, reranker), keeping one vector per token rather than one per passage. It loads PyLate, Stanford ColBERT and colpali-engine checkpoints through a single API.
</p>

<p style="margin: 0 0 16px; font-size: 15px; color: #f5f5f0; line-height: 1.6;">
<strong style="color: #f7ff00;">How does it work?</strong><br>
Scoring uses MaxSim: for each query token, take the highest similarity against any document token, then sum. Token-level detail preserves exact matches and synonyms that dense embeddings average away — at the cost of larger index size (~92 MB compressed vs. 7.5 MB for a dense index on the same corpus).
</p>

<p style="margin: 0 0 16px; font-size: 15px; color: #f5f5f0; line-height: 1.6;">
<strong style="color: #f7ff00;">Why does it matter?</strong><br>
RAG teams no longer need a second framework to try late interaction. The multi-vector LateOn model scores 0.6868 NDCG@10 on NanoBEIR vs. 0.6764 for its dense counterpart, and Qdrant, Weaviate, Vespa and LanceDB already support MaxSim natively.
</p>

<p style="margin: 0 0 20px; font-size: 15px; color: #f5f5f0; line-height: 1.6;">
<strong style="color: #f7ff00;">Who is it for?</strong><br>
RAG and search engineers who want to compare dense, sparse, reranking and multi-vector retrieval under one unified training and evaluation loop.
</p>
